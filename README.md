# Pencil2Diamond

**Pencil2Diamond**는 연필에서 흑연을 얻고, 이를 가공해 다이아몬드를 만드는 Unity 기반 2D 성장형 미니게임 프로젝트입니다.

현재는 튜토리얼과 메인 공방을 연결하는 MVP를 개발 중입니다. 튜토리얼의 연필 깎기, 흑연 추출, 프레스 성공/실패 대화 분기, 다이아몬드 획득·판매와 메인 화면 진입이 코드에 연결되어 있습니다. 메인 공방에는 작업 선택, 공통 수량 선택 UI, 연필 상점과 기본 구매 처리를 추가했습니다.

메인 게임에서 선택 수량에 따른 제작·자원 소비·보상·판매를 반복하는 루프와 저장/불러오기는 아직 완성되지 않았습니다. 아래 구현 상태는 코드와 씬 설정을 기준으로 정리했으며, Unity Play Mode와 Android 기기에서의 동작 검증은 별도로 필요합니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | Pencil2Diamond |
| 장르 | 2D 캐주얼 / 성장형 제작 미니게임 |
| 엔진 | Unity `6000.4.0f1` |
| 목표 플랫폼 | Android |
| 개발 목적 | Unity 클라이언트 신입 지원용 포트폴리오 |
| 개발 방식 | 기능 단위 구현 → 동작 확인 → 문서화 → PR 검토 → 통합 |

Unity 버전은 [ProjectVersion.txt](ProjectSettings/ProjectVersion.txt), 패키지 구성은 [manifest.json](Packages/manifest.json)을 기준으로 합니다. 주요 패키지는 URP 2D, TextMeshPro/uGUI, Input System, UniTask입니다.

## 2. 게임 흐름

### 2.1 튜토리얼에 연결된 흐름

```text
시작 화면
→ TSV 기반 대화
→ 연필 깎기
→ 흑연 추출·획득
→ 프레스 온도 판정
   ├─ 실패: 실패 대화 → 재시도
   └─ 성공: 다이아몬드 획득
→ 판매 대화·코인 획득
→ 튜토리얼 종료
→ 메인 공방 진입
```

프레스 판정과 보상은 튜토리얼 대화 명령에 연결된 흐름입니다. 일반 플레이의 제작 수량 처리와 반복 보상 시스템까지 구현된 상태는 아닙니다. 현재 씬의 프레스 컴포넌트 참조도 점검이 필요합니다.

### 2.2 메인 공방의 현재 흐름

```text
메인 공방
├─ 연필 깎기 / 프레스 선택 → 보유량·수량 설정 → 작업 화면 전환
└─ 연필 상점 → 목록 → 상세 정보·수량 선택 → 구매 기본 처리
```

### 2.3 목표 반복 루프

```text
연필 구매·선택
→ 연필 깎기
→ 흑연 획득
→ 프레스 가공
→ 다이아몬드 생성
→ 판매·코인 정산
→ 장비·효율 업그레이드
→ 반복
```

최종 목표는 짧은 시간 안에 반복 가능한 1분 성장 루프를 완성하는 것입니다.

| 연필 깎기·흑연 추출 | 튜토리얼 연필 데이터 로드, 작업 완료 이벤트, 흑연 획득 | 메인 플레이의 선택 연필·수량·자원 소비 연결 |

| 메인 공방 진입 | 튜토리얼 종료 후 `Workshop` 상태 전환과 메인 UI 표시 | 반복 작업과 재진입 검증 |
| 메인 메뉴·재화 표시 | 공방 정보, 코인·다이아몬드 표시, 메뉴 버튼 이벤트 | 구매 직후 표시 갱신, 미션·업그레이드 기능 |
| 작업 목록·수량 선택 | 보유량 표시, 수량 범위 제한, 보유량 0일 때 시작 비활성화, 작업 화면 전환 | 선택 수량만큼 실제 가공·자원 소비 처리 |
| 연필 상점 | 데이터 기반 목록 생성·배치, 이름·설명 표시, 상세 화면·목록 이동 | 추가 연필 에셋의 씬 등록 |
| 연필 구매 | 수량 변경 시 잔액 비교, 구매 시 코인 차감·미가공 연필 수 증가 | 최초 진입·연속 구매 검증, 거래 시 재검증, 종류별 재고 관리 |
| 저장/불러오기 | `GameProgressData` 데이터 모델 선언 | 저장·로드 호출, 튜토리얼 완료 상태와 재화 복원 |
| Android 빌드 | Android 빌드 프로필 존재 | 개발 전용 조건부 코드 정리, 빌드·터치·실기기 검증 |

### 3.1 현재 제한

- 메인 작업의 시작 버튼은 작업 화면으로 전환하지만, 선택한 수량을 실제 가공에 사용하지 않습니다. `PencilManager.MainGameMode()`의 연필 슬롯 연결과 메인 흑연 추출 분기도 남아 있습니다.
- 구매 처리는 UI의 잔액 비교와 코인 차감·연필 수 증가까지 연결되어 있습니다. 상세 화면 최초 표시와 구매 직후의 버튼 재평가, 거래 시 잔액 재검증, 인벤토리 변경 이벤트를 통한 표시 갱신은 추가 구현이 필요합니다.
- 연필 재고는 미가공 연필의 총수량으로 관리합니다. 현재 씬에서 상점에 등록된 연필은 2B와 4B이며, Golden/Diamond 연필 에셋은 씬에 등록되지 않았습니다.
- `UIManager`가 참조하는 `SettingTemperature`와 실제 온도 UI·확인 버튼이 연결된 인스턴스가 달라, 목표 온도 전달과 버튼 판정을 점검해야 합니다.
- `GameProgressData`에는 저장할 항목이 선언되어 있지만 저장·복원 로직은 없습니다. `PlayerData`의 ScriptableObject 값과 실행 중 상태 변경을 앱 재실행 후 복원 기능으로 간주하지 않습니다.
- `StartMenuUI`의 개발용 메서드 호출과 `TutorialFlowController`의 개발용 필드에 적용된 컴파일 조건이 일치하지 않습니다. Android 일반 빌드와 Development Build 모두 조건부 코드 정리 후 확인해야 합니다.

## 4. 실행 및 확인 방법

### 4.1 Unity 에디터에서 메인 공방 확인

1. 저장소를 내려받고 Unity Hub에서 프로젝트 루트 폴더를 추가합니다.
2. Unity `6000.4.0f1`로 열고 패키지 설치와 에셋 임포트가 끝날 때까지 기다립니다. UniTask는 Git URL로 등록되어 있어 패키지 설치 시 Git과 네트워크 접근이 필요합니다.
3. [MainScene](Assets/Scenes/MainScene.unity)을 열고 Play Mode를 시작합니다.
4. 시작 버튼을 누릅니다. 현재 씬은 개발용 메인 공방 진입 설정이 켜져 있으며, `MainGameStartForDev()`는 코인을 200, 다이아몬드를 0으로 설정합니다.
5. 연필 깎기·프레스 버튼의 작업 목록, 보유량에 따른 수량 제한, 상점의 연필 목록·상세 정보·구매 흐름을 확인합니다.

개발용 진입은 튜토리얼을 건너뛰는 테스트 경로입니다. 저장 데이터에서 진행 상태를 복원하는 경로는 아닙니다.

### 4.2 튜토리얼 확인

Play Mode 시작 전에 Inspector에서 다음 두 설정을 모두 변경합니다.

- `PanelStart` 오브젝트의 `StartMenuUI`: **Start From Workshop For Dev** 해제
- `TutorialFlowController` 오브젝트의 `TutorialFlowController`: **Current Game Phase**를 `Tutorial`로 설정

현재 씬은 `Current Game Phase`도 `Workshop`으로 저장되어 있어 개발용 옵션만 해제하면 튜토리얼을 건너뜁니다. 프레스 단계는 3.1의 컴포넌트 참조 제한을 함께 확인해야 합니다.

### 4.3 검증 범위

이 README 갱신에서는 코드, 대화 데이터, 에셋, 씬 참조와 문서 경로를 확인했습니다. Unity Play Mode, 빌드, Android 실기기 테스트 결과는 포함하지 않습니다.

## 5. 씬 및 시스템 구조

현재 실행 씬은 `MainScene` 하나이며, UI 패널 전환으로 시작 화면·튜토리얼·메인 공방·상점·작업 화면을 연결합니다.

| 구분 | 주요 구성 | 역할 |
| --- | --- | --- |
| 흐름 제어 | `TutorialFlowController`, `MainFlowController`, `MainMarketController` | 튜토리얼 단계, 메인 작업 진입, 상점 선택·구매 흐름 |
| 대화 | `TalkManager`, `DialogManager` | TSV 대화 파싱, 출력, 명령과 성공/실패 분기 |
| 작업 | `PencilManager`, `SharpeningPencil`, `PencilCollectedGraphite`, `SettingTemperature` | 연필 데이터 선택, 깎기, 흑연 추출, 온도 판정 |
| 인벤토리 | `PlayerInventoryManager`, `PlayerData` | 연필·흑연·다이아몬드·코인 수량과 변경 이벤트 |
| 화면 | `UIManager`, `StartMenuUI`, `MainMenuUI`, `MainWorkshopUI` | 캔버스·작업 패널 전환, 시작 화면, 메인 메뉴·공방 입력 |
| 작업·상점 UI | `WorkListUI`, `MainMarketUI`, `ItemDetailInfoUI`, `QuantitySettingUI` | 목록·상세 정보 표시와 공통 수량 선택 |
| 표시 데이터 | `WorkListViewData`, `ShopListViewData`, `ShopItemInfoViewData` | 컨트롤러가 UI에 전달하는 작업·상점 표시 데이터 |

- `GamePhase`는 튜토리얼과 메인 공방 같은 게임의 큰 흐름을 구분합니다.
- `TutorialStep`은 튜토리얼 진행 단계, `WorkingStep`은 작업 종류를 구분합니다.
- 대화 원본은 [TutorialDialog.txt](Assets/Asset/Dialog/TutorialDialog.txt)에 탭으로 구분된 데이터로 관리합니다.
- 연필·흑연·다이아몬드·공방 설정은 ScriptableObject 에셋으로 관리합니다.

## 8. 개발 규칙

### 8.1 브랜치

| 브랜치 | 용도 |
| --- | --- |
| `main` | 안정 버전, 시연 가능한 상태 |
| `develop` | 개발 통합 |
| `feature/*` | 새 기능 개발 |
| `fix/*` | 버그 수정 |
| `refactor/*` | 구조 개선 |
| `docs/*` | 독립적인 문서 작업 |

기능 구현에 따른 README 갱신은 해당 기능 브랜치에 함께 커밋할 수 있습니다. 기능 브랜치의 PR은 `develop`을 대상으로 작성하고, 검토와 동작 확인 후 병합합니다.

### 8.2 커밋 메시지

```text
type: 작업 내용
```

| 타입 | 의미 | 예시 |
| --- | --- | --- |
| `feat` | 기능 추가 | `feat: 연필 구매 흐름 추가` |
| `fix` | 버그 수정 | `fix: 상점 수량 초기화 수정` |
| `refactor` | 구조 개선 | `refactor: 메인 화면 UI 책임 분리` |
| `docs` | 문서 수정 | `docs: README 구현 현황 갱신` |
| `chore` | 설정 및 기타 작업 | `chore: 생성 파일 제외 규칙 추가` |
| `test` | 테스트 추가 | `test: 저장 데이터 검증 추가` |

### 8.3 PR과 동작 확인

기능 단위 브랜치에서 구현하고 Unity 에디터에서 확인한 뒤, 변경 내용·검증 결과·남은 작업을 README와 PR에 정리합니다. 실행하지 않은 검증 항목은 완료로 표시하지 않습니다.

## 9. 포트폴리오에서 강조할 점
